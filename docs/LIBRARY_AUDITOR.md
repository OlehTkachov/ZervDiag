# ZervDiag Library Auditor

Отдельная утилита для ревизии большой технической библиотеки без ручного открытия тысяч файлов.

## Главное правило безопасности

Library Auditor **не удаляет файлы автоматически**.

Он читает существующую `data/zervdiag.db`, присваивает каждому файлу ориентировочную оценку полезности и разбивает библиотеку на три группы:

- **Вероятно полезные** — 75–100 баллов;
- **Нужно проверить** — 45–74 балла;
- **Подозрительные** — 0–44 балла.

Оценка — это только подсказка, а не решение об удалении.

## Что учитывается

Положительные признаки:

- технический формат документа;
- модель/технический код в имени или пути;
- технические слова в имени, пути или извлечённом тексте;
- достаточный объём уже извлечённого текста;
- успешный статус индексации.

Отрицательные признаки:

- временные/резервные имена (`~$`, `tmp`, `backup`, `old`, `копия` и т. п.);
- нулевой или очень маленький размер;
- медиа/исполняемые форматы;
- неподдерживаемый формат;
- ошибка извлечения.

Правила специально сделаны осторожными: фотография или архив не объявляются мусором только из-за расширения.

## Нагрузка

Утилита не открывает 10 000 документов и не запускает OCR повторно.

Для оценки используется уже существующая SQLite-база. Из текста каждого документа берётся только небольшой образец (до первых 20 000 символов) плюс общая длина текста.

OneDrive-файлы при анализе не гидратируются.

## Интерфейс

### Файлы

Можно фильтровать:

- все;
- подозрительные;
- нужно проверить;
- вероятно полезные.

Есть дополнительный текстовый фильтр по имени, пути, расширению и причинам оценки.

Доступны:

- открыть выбранный файл;
- показать его в Проводнике;
- экспортировать текущую выборку в CSV;
- переместить выбранные локальные файлы в карантин.

### Папки и типы

Показывает распределение по папкам или расширениям:

- всего файлов;
- подозрительных;
- требующих проверки;
- вероятно полезных.

Это позволяет быстро найти папки, в которых сосредоточен мусор.

### Повторяющиеся имена

Показывает одинаковые имена в разных папках. Это предварительный сигнал, а не доказательство клона.

Точные клоны по содержимому по-прежнему проверяются отдельным механизмом ZervDiag.

## Карантин

Карантин — безопасная альтернатива удалению.

Выбранные **локальные** файлы перемещаются в указанную папку с сохранением структуры каталогов. Облачные файлы автоматически не перемещаются, чтобы случайно не вызвать массовую работу OneDrive.

В папке карантина создаётся журнал:

`zervdiag_quarantine_log.csv`

После завершения ревизии нужно запустить обычную индексацию ZervDiag, чтобы основная база увидела перемещённые файлы.

## Запуск

После переключения на ветку `library-auditor`:

```powershell
python run_library_auditor.py
```

На рабочем компьютере используйте тот же Python, которым запускается ZervDiag.

## Рекомендуемый порядок работы

1. Дождаться завершения текущего OCR.
2. Сделать резервную копию `zervdiag.db` через SQLite backup API.
3. Запустить Library Auditor.
4. Сначала посмотреть вкладку «Папки и типы».
5. Затем фильтр «Подозрительные».
6. Экспортировать сомнительную выборку в CSV при необходимости.
7. Только после просмотра перемещать выбранные файлы в карантин.
8. Не удалять карантин сразу — оставить его на некоторое время.
9. После ревизии выполнить обычную индексацию ZervDiag.
