# SOOSAN JK1200A — регламент полевого CAN-захвата

## Неподвижные правила

PCAN-View остаётся главным регистратором. CraneCAN анализирует сохранённый
`.trc`; в полевой сборке CraneCAN нет live-драйвера и нет функций передачи.

- PCAN: `250 kbit/s`, Classical CAN 2.0.
- Обязательно включить `Listen-only`.
- Принимать Standard 11-bit и Extended 29-bit одновременно.
- Все фильтры при записи полностью открыть.
- Передачу кадров запретить.
- Дополнительную терминацию PCAN выключить.
- Подключать PCAN параллельно через проверенный переходник.
- Не разрывать штатный обмен HCH2/HCL2.

## Подготовка до запуска двигателя

- [ ] Переходник проверен омметром и подписан: CAN-H, CAN-L, GND.
- [ ] Штатные устройства остаются соединёнными.
- [ ] PCAN подключён параллельно, дополнительного `120 Ом` нет.
- [ ] PCAN-View видит PCAN-USB.
- [ ] Выбран канал HCH2/HCL2, `250 kbit/s`, Listen-only.
- [ ] Фильтры Standard/Extended полностью открыты.
- [ ] На ноутбуке достаточно свободного места, часы проверены.
- [ ] CraneCAN открывает контрольный TRC и сохраняет CSV сравнения.

При сомнении в распиновке двигатель не запускать и сеть не подключать.

## Главная запись понедельника

1. Собрать штатную сеть и подключить PCAN к `HCH2 / HCL2` параллельно.
2. Запустить двигатель.
3. Установить `1150–1200 rpm`.
4. Дождаться полной зарядки LPU и готовности системы.
5. Начать новую Trace-запись PCAN-View.
6. Не воздействовать на органы управления 10–15 секунд: это REFERENCE.
7. Задать длину стрелы больше фактической.
8. Отклонить джойстик EXTEND примерно на 2–3 секунды.
9. Если движение началось — сразу вернуть джойстик в нейтраль.
10. После воздействия записывать ещё не менее 5 секунд.
11. Остановить запись и сохранить исходник:

```text
JK1200A_HCH2_engine_1200rpm.trc
```

12. Исходный файл не редактировать. Для обработки делать копию.
13. Отдельно записать фактические моменты REFERENCE и EXTEND по таймеру или
    видео, чтобы корректно задать окна CraneCAN.

## Анализ одной записи в CraneCAN

1. Открыть `.trc` кнопкой `Открыть PCAN-View TRC`.
2. Проверить число кадров и диагностику пропущенных RTR/error/unknown строк.
3. На вкладке кадров проверить наличие Standard и Extended ID.
4. На вкладке статистики проверить частоты и периоды интересующих ID.
5. Открыть вкладку `REFERENCE → ACTION`.
6. Ввести границы REFERENCE в миллисекундах от начала трассы.
7. Ввести границы установившегося ACTION; не включать в окно возврат в нейтраль.
8. Нажать `Сравнить окна`.
9. Сначала оставить `Только значимые изменения`.
10. Проверить строки с очень высоким и высоким приоритетом.
11. Снять флажок и проверить полный результат, включая нестабильные строки.
12. Сохранить CSV. CSV всегда включает полный результат.

Если внутри выбранного окна нет обычных Rx DATA-кадров, CraneCAN прекращает
сравнение и просит исправить границы. Пустое окно нельзя трактовать как
исчезновение всех сообщений.

## Альтернатива — два отдельных файла

Если условия позволяют, записать два файла одинаковой продолжительности:

- `REFERENCE`: готовая система, джойстик в нейтрали, 10–20 секунд;
- `ACTION_EXTEND`: те же условия, одно воздействие EXTEND после стабилизации.

На вкладке сравнения выбрать оба файла и нажать `Сравнить файлы`.

## Что особенно проверять в HCH2

Полная HYDAC/J1939-декодировка пока не требуется. Важно сохранить и сопоставить
последовательность событий:

1. двигатель;
2. состояние LPU;
3. RM05 / LMB;
4. джойстик;
5. AUTO_IDLE / AUTO_PICKUP;
6. выбранная секция;
7. целевая позиция;
8. направление EXTEND;
9. рассчитанное перемещение;
10. уставка клапанов;
11. фактический ток Y060/Y061.

Приоритетные известные ID:

| ID | Рабочая роль / предмет проверки |
|---|---|
| `0x0CF00400` | обороты двигателя |
| `0x18012101` | исходное 29-bit сообщение HYDAC |
| `0x0CFF1421` | обработанный джойстик EXTEND |
| `0x0CFF2221` | сохранить для последующей декодировки |
| `0x18800121` | сохранить для последующей декодировки |
| `0x0CFF2121` | секция / цель / направление |
| `0x0CFF3621` | AUTO_IDLE ↔ AUTO_PICKUP |
| `0x0CFF5821` | restricted modes, особенно RM05 |
| `0x188C0121` | AUTO / LMB |
| `0x18740121` | сохранить для последующей декодировки |
| `0x18720121` | уставка клапанов телескопического цилиндра |
| `0x0CFF5321` | фактический ток Y060/Y061 |

Из предыдущей записи известно: TTC60 принимает цель, видит джойстик,
формирует AUTO_PICKUP и направление EXTEND, RM05 равен 0, рассчитанное движение
есть. Новый ключевой вопрос:

> Появится ли команда/ток Y060 при работающем двигателе и заряженной LPU?

- Если Y060 появляется — проверять силовую электрическую и гидравлическую цепь.
- Если разрешения присутствуют, но Y060 остаётся нулём — искать внутреннее
  условие TTC60 или конфигурации.

## Контроль Comparator на JCH4

Для Standard ID `0x18F` ранее наблюдалось:

```text
REFERENCE: 08 00 00 00 00
ACTION:    08 02 C8 00 00
RETURN:    08 02 C7 00 00 → 00 00 00 00 00
```

CraneCAN должен показать устойчивые изменения `DATA[1]` и `DATA[2]`, XOR и
переходы битов. Это контроль корректности анализа, а не готовая расшифровка
SOOSAN HCH2.

## Что сохранить после испытания

- исходный `.trc` PCAN-View;
- CSV сравнения CraneCAN;
- фото точки подключения и настроек PCAN-View;
- время начала/конца REFERENCE и ACTION;
- обороты двигателя, состояние LPU и фактическое движение;
- заметку, появился ли ток/команда Y060.

Не переименовывать и не перезаписывать исходный TRC после возвращения с полигона.
