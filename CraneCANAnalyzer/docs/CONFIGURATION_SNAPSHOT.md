# Read-only Configuration Snapshot — CraneCAN 0.7

## Назначение

`Configuration Snapshot` сохраняет наблюдаемое состояние CAN-шины из уже
открытого TRC и связывает его с текущим Machine Profile. Это **не** чтение
параметров ECU, не резервная копия контроллера и не сервисная конфигурация.

Функция полностью пассивная: CAN Tx не используется.

## Что сохраняется

Файл `*.cansnapshot` содержит:

- имя исходного TRC без абсолютного пути;
- данные текущего Machine Profile: машина, производитель, модель, CAN bus,
  известный bitrate профиля;
- начало/конец и длительность наблюдаемой трассы;
- число обычных Classical CAN Rx-кадров;
- список Standard/Extended ID;
- число кадров каждого ID;
- встречавшиеся DLC;
- modal DLC и процент его повторяемости;
- modal DATA и agreement каждого байта;
- средний, минимальный и максимальный период и оценочную частоту;
- список известных/экспериментальных сигналов профиля и признак, наблюдался ли
  соответствующий CAN ID в этой трассе.

Tx, RTR и error-кадры в snapshot состояния не включаются.

## Что snapshot НЕ утверждает

Наличие ID или устойчивого байта не доказывает назначение сигнала. Значение
`profileBitrate` берётся только из Machine Profile и не определяется из TRC.
Snapshot не содержит скрытых параметров HYDAC/ECU, сервисных паролей или
заводской конфигурации, если эти данные не наблюдались в CAN и не были ранее
добавлены пользователем в профиль.

Основное применение — сохранить воспроизводимую read-only точку наблюдения,
сравнить машину до/после ремонта и в дальнейшем использовать как основу для
контролируемого GOOD/FAULT сравнения.
