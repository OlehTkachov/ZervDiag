# Запись предыстории события — CraneCAN 0.7 development

## Что реализовано

На вкладке LIVE GUIDED доступны кнопки «ОТМЕТИТЬ СОБЫТИЕ (−10 / +5 с)»,
«Сохранить запись события…» и «Открыть .canincident…». Приёмник постоянно
хранит ограниченную предысторию Classical CAN Rx. Отметка фиксирует последние
10 секунд и продолжает запись следующих 5 секунд времени CAN-кадров. Название
отметки берётся из выбранного действия. Для реального PCAN Guided-эксперимент
не обязателен: достаточно подключённого потока.

Replay теперь воспроизводится с обычной скоростью, чтобы можно было читать
инструкции и отмечать события вручную. Ускоренный режим драйвера по-прежнему
доступен в Core и используется smoke tests.

## Проверка без машины

1. Подключить `TRC Replay` с `samples/live_guided_demo.trc`.
2. Запустить Guided с длительностями 5 / 3 / 10 / 5 секунд.
3. После накопления примерно 11–13 секунд записи нажать «ОТМЕТИТЬ СОБЫТИЕ».
4. Дождаться ещё 5 секунд записи. Появится результат полноты.
5. Нажать «Сохранить запись события…» и выбрать папку вне `publish`.
6. Нажать «Открыть .canincident…», выбрать сохранённый `incident.canincident`
   и проверить timeline: начало окна, отметку, первый/последний CAN-кадр и
   правую границу.
7. В окне timeline нажать «Открыть capture.trc в анализаторе» и убедиться,
   что выборка открылась на вкладке `Generic CAN — кадры`.

Необязательно повторять один демофайл три раза: этот тест проверяет только
сохранение и повторное открытие предыстории, а не доказательство физической
неисправности.

## Модель времени и качества

Отметка привязана к последнему принятому кадру. Это приближение времени
нажатия оператором, а не аппаратный trigger; при редком трафике погрешность
равна возрасту последнего кадра. Окно полуоткрытое `[marker−10s, marker+5s)`.
Полнота post-window устанавливается при приёме кадра на/после правой границы.
Если шина замолчала, завершение не симулируется настенными часами: остановка
приёма сохраняет неполную запись с `POST_INTERRUPTED`.

Повторная отметка в активном окне добавляется к тому же событию (максимум 32),
не расширяя окно. Перед новым событием UI требует сохранить предыдущее.
История и одна запись ограничены каждая 100 000 кадрами. Полный непрерывный
raw TRC продолжает сохраняться существующим приёмником независимо от этой
выборки.

Коды качества сохраняются в JSON, русский текст формируется интерфейсом:

| Код | Значение |
|---|---|
| SHORT_PREHISTORY | До отметки не накоплено 10 секунд наблюдения |
| PREHISTORY_FRAME_LIMIT | Часть предыстории вытеснена лимитом кадров |
| FRAME_LIMIT | Запись события достигла лимита кадров |
| POST_INTERRUPTED | Приём остановлен до полного post-window |
| CAPTURE_UNCERTAIN | Обнаружены потери/ошибки или неподтверждённый listen-only |
| OUT_OF_ORDER | Нарушен порядок timestamps |

Флаг `complete` означает только полноту наблюдаемого окна по доступным
признакам регистрации. Он не подтверждает исправность машины или причинную
связь событий. Счётчики ошибок учитываются консервативно с начала подключения.

## Формат, повторное открытие и переносимость

Каждый экспорт создаёт уникальную папку:

- `capture.trc` — кадры окна без изменения payload, ID, формата и канала;
- `incident.canincident` — JSON schema 1: ID, времена, отметки, качество,
  число кадров, driver/channel/bitrate, Replay provenance и ссылка на raw TRC.

`rawTracePath` внутри JSON относительный (`capture.trc`). Переносить следует
всю папку. Источник непрерывного capture и исходный Replay указаны отдельно
как provenance; для открытия выборки они не нужны.

При повторном открытии CraneCAN проверяет schema, границы окна, отметки,
согласованность `complete` с кодами качества, наличие `capture.trc`, число
кадров и то, что timestamps кадров остаются внутри сохранённого окна.
Абсолютный путь и `..` в `rawTracePath` отклоняются: связанный TRC должен
оставаться внутри incident-папки. После проверки показывается timeline
относительно первой отметки; связанный `capture.trc` можно сразу открыть
в обычном offline-анализаторе.

Экспорт TRC дополнен абсолютной UTC-меткой `;$CRANECAN_STARTUTC`, сохраняющей
точный origin при чтении в другом часовом поясе. Стандартный `$STARTTIME`
записывается в локальном времени для PCAN. Старые TRC не переписываются;
исправление времени относится к новым экспортам.

## Проверки и дальнейшая работа

Smoke tests проверяют границы окна, объединение отметок, короткую предысторию,
остановку, лимиты памяти, признаки потерь, копирование DATA, JSON/TRC экспорт,
сохранение абсолютного времени, повторное открытие пакета, защиту относительного
пути и отсутствие перезаписи повторного экспорта.

Следующие этапы: автоматические triggers по Node Health, GOOD/FAULT First
Divergence и read-only Configuration Snapshot. Этот этап не добавляет CAN Tx
и не устанавливает физическую причину события автоматически.
