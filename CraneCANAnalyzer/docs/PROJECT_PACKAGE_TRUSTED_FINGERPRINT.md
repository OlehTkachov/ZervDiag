# CraneCAN — External Trusted Project Package Fingerprint

## Назначение

При экспорте Project Package CraneCAN создаёт рядом с ZIP отдельный файл:

```text
<package>.zip.cranefingerprint.json
```

Он не входит внутрь ZIP и содержит контрольную идентичность конкретной
контрольной копии:

- Project ID;
- имя корневого `.canproject`;
- имя ZIP;
- размер ZIP;
- SHA-256 всего ZIP;
- SHA-256 внутреннего `CraneCAN.package-manifest.json`;
- время создания fingerprint.

## Зачем нужен внешний fingerprint

Внутренний package manifest хорошо обнаруживает изменение одного или нескольких
payload-файлов относительно manifest. Но если кто-то одновременно заменит и
payload, и внутренний manifest, новый ZIP снова может быть внутренне
согласованным.

Внешний fingerprint решает именно эту задачу при одном обязательном условии:
его нужно получить или хранить **отдельно от ZIP по независимому доверенному
каналу**.

Например:

- ZIP передан через облако или USB;
- `.cranefingerprint.json` сохранён в отдельном архиве инженера;
- либо fingerprint отправлен отдельно другому инженеру.

Если ZIP и fingerprint находятся только рядом и передаются одним и тем же
недоверенным способом, это удобная контрольная пара, но не независимое
доказательство происхождения.

## Экспорт

`Экспорт ZIP…` после полной проверки package автоматически создаёт sidecar:

```text
SOOSAN_package.zip
SOOSAN_package.zip.cranefingerprint.json
```

Fingerprint записывается только после того, как ZIP успешно создан и проверен.

Если sidecar не удалось сохранить, CraneCAN явно предупреждает об этом.
Старый sidecar нельзя считать доверенным для нового ZIP.

## Проверка

`Проверить ZIP…` сначала выполняет обычную внутреннюю проверку package без
распаковки.

Затем:

1. если рядом с ZIP найден `<zip>.cranefingerprint.json`, он используется
   автоматически;
2. если sidecar рядом отсутствует, инженер может выбрать fingerprint из другой
   папки;
3. если fingerprint не выбран, проверка остаётся обычной внутренней проверкой.

Внешняя проверка сравнивает:

- Project ID;
- размер ZIP;
- SHA-256 всего ZIP;
- SHA-256 внутреннего package manifest;
- имя корневого `.canproject`.

Имя самого ZIP не является частью обязательного сравнения содержимого: архив
можно переименовать без потери доверенного совпадения, если его байты, Project ID
и внутренний manifest остались теми же.

## Статусы

### `TRUSTED MATCH`

ZIP прошёл внутреннюю проверку и совпал с выбранным внешним fingerprint.

### `TRUSTED MISMATCH`

ZIP внутренне согласован, но не совпадает с внешней контрольной копией.
Такой результат нужно рассматривать как отдельную проблему целостности или
как признак того, что выбран fingerprint от другого package.

### `VALID / NO TRUSTED FINGERPRINT`

ZIP внутренне валиден, но внешний fingerprint не предоставлен. Это не ошибка
package, однако независимое сравнение с контрольной копией не выполнялось.

### `INVALID`

Сам ZIP не прошёл внутреннюю проверку. Внешний fingerprint не может сделать
такой package валидным.

## Что fingerprint не делает

SHA-256 и sidecar не являются цифровой подписью.

Даже `TRUSTED MATCH` доказывает совпадение байтов с конкретной контрольной
копией только в той мере, в какой сам внешний fingerprint был получен из
доверенного источника.

Fingerprint:

- не доказывает личность автора;
- не содержит закрытого ключа;
- не выполняет сетевую проверку сертификатов;
- не открывает CAN;
- не выполняет CAN Tx.

Для криптографического доказательства авторства в будущем потребуется
отдельная цифровая подпись.

## Безопасность CAN

Функция полностью офлайн. Она работает только с файлами package и не меняет
receive-only / LISTEN ONLY архитектуру CraneCAN.
