# CraneCAN 0.6 — Generic Guided Diagnostics

## Назначение

CraneCAN переводит понятный сервисному инженеру физический эксперимент в
ранжированный список наблюдаемых CAN-кандидатов. Для начала исследования не
нужны DBC, J1939 database, известный CAN ID или знание endian/scaling.

Программа анализирует факты в трассе и не утверждает, что знает внутреннюю
логику ECU. Формулировка результата — «кандидат на сигнал» или «сильно
коррелирует с действием», пока пользователь не добавил независимое evidence.

## Три уровня

1. **Generic CAN Core** читает Classical CAN, различает Standard/Extended,
   сравнивает состояния, анализирует последовательности значений и считает
   статистику. В Core нет условий по марке машины или известному ID.
2. **Guided Diagnostics** хранит REFERENCE/ACTION-повторы, оценивает качество
   эксперимента, обнаруживает фронт около примерного времени, ранжирует
   кандидатов и формирует timeline.
3. **Machine Profile** хранит подтверждённые и экспериментальные знания в
   человекочитаемом JSON с расширением `.craneprofile`. Профиль не является
   частью исходного кода Core.

## Статусы знания

| Статус | Значение |
|---|---|
| `UNKNOWN` | Сигнал ещё не исследован. |
| `CANDIDATE` | Наблюдается корреляция, подтверждения недостаточно. |
| `PROBABLE` | Есть повторяемые данные и/или дополнительное evidence. |
| `CONFIRMED` | Пользователь подтвердил назначение независимым evidence. |
| `REJECTED` | Кандидат проверен и отклонён с сохранением причины. |

CraneCAN не повышает статус до `CONFIRMED` автоматически. Даже score 100/100
остаётся измерением качества наблюдаемой корреляции.

## Эксперимент

Минимальная единица анализа — пара `REFERENCE` (спокойное состояние) и
`ACTION` (одно понятное физическое действие). Один `.trc` может содержать оба
временных окна. Несколько записей добавляются как повторы 1, 2, 3 и далее.
Эксперимент сохраняется в открытом JSON с расширением `.canexperiment`; большие
TRC остаются отдельными файлами, в документе хранятся пути и metadata.

Если пользователь указывает примерное время действия, analyzer ищет первый
устойчивый фронт внутри настраиваемого допуска `±`. При пустом поле момент
действия определяется автоматически по первому расхождению со стабильным
REFERENCE.

## Temporal / Transition Analyzer

Для каждого изменившегося `ID / DATA[n]` сохраняются значение REFERENCE,
первое изменённое значение и timestamp, последовательность значений, min/max,
последнее устойчивое значение, время стабилизации, возврат к baseline, скорость,
монотонность, число переходов и номера повторов.

Поэтому последовательность `00 → 02 → 0F → 11 → C8` распознаётся как
переходный ramp, а не теряется в одном modal-consensus.

## Repeatability

Одинаковый кандидат идентифицируется по CAN ID, формату Standard/Extended,
DATA index и bit index для одиночного перехода. Standard `0x123` и Extended
`0x00000123` всегда считаются разными сообщениями. В UI показывается `3/3`,
`2/3` и т. п. Низкая repeatability снижает score.

## Прозрачный Confidence Score

Score ограничен диапазоном 0–100 и складывается из отображаемых вкладов:

| Факт | Баллы |
|---|---:|
| Повторяется во всех 3 или более опытах | +30 |
| Повторяется во всех имеющихся 1–2 опытах | +15 |
| Стабильный переход одного бита | +25 |
| Стабильное изменение байта | +18 |
| Появление/исчезновение ID | +25 |
| Направленный analog ramp | +12 |
| Возникает после действия | +20 |
| Возвращается к baseline | +15 |
| Agreement не ниже 95% | +10 |
| Низкая repeatability | −30 |
| Вероятный analog noise | −25 |
| Изменение начинается до действия | −20 |

Выбор кандидата показывает каждое слагаемое. Скрытый «AI confidence» не
используется.

## Machine Profile и evidence

Профиль содержит manufacturer, model, optional serial number, subsystem, bus,
bitrate, CAN type, program/schema version, известные и экспериментальные
сигналы, отклонённые кандидаты, notes и timestamps. Для сигнала сохраняются
CAN ID и формат, byte/bit/length, endian, signed/unsigned, scale, offset, unit,
enum states, status, evidence и source.

Evidence может ссылаться на повторный опыт, схему, документацию, DBC, service
software, измерение или пользовательское подтверждение.

## Защита от ошибок оператора

До ранжирования проверяются наличие кадров REFERENCE/ACTION, минимальное число
кадров и длительность, пересечение окон одного TRC, одинаковый bus, наличие
границы действия и repeatability. Ошибки делают эксперимент непригодным и
блокируют список кандидатов. Предупреждения остаются видимыми.

## Безопасность

Offline pipeline по-прежнему работает только с сохранёнными трассами. В 0.7
добавлен отдельный Live-источник PCAN, но он требует аппаратно подтверждённый
Listen-only, а его сборка не содержит transmit API. PCAN-View остаётся основным
полевым регистратором. Программа не предлагает прямую подачу питания, обход
блокировок или отключение защит.

## SOOSAN regression

SOOSAN JK1200A используется только как реальная regression fixture. Общий код
не содержит условий по `0x18F` или HYDAC ID. Smoke-тест подтверждает Standard
`0x18F`, `DATA[1] 00 → 02`, `DATA[2] 00 → C8`, Extended 29-bit HYDAC IDs,
разделение Standard/Extended, ramp/transition и noise ranking.

## Состояние в 0.7

Offline Guided UI, повторы, temporal analysis, score/explanation, quality
checks, profile и experiment persistence дополнены общим Live/Replay pipeline.
На следующие этапы оставлены интерактивный график, event-chain GOOD/FAULT
divergence, `.canproject`, Signal Builder, streaming parsing больших TRC,
DBC/J1939 decoding, adaptive experiment selection и AI integration.
