# CraneCAN — Project Integrity

## Назначение

Project Integrity проверяет целостность рабочего `*.canproject` перед переносом
проекта, повторным анализом или полевой диагностикой.

Проверка полностью офлайн: она читает только manifest и зарегистрированные
локальные файлы. CAN Tx не используется.

## Строгая целостность manifest

`CraneProjectCodec` теперь проверяет `traceBindings` при каждом сохранении и
открытии `*.canproject`.

Manifest отклоняется, если persistent binding:

- имеет пустой или повторяющийся `bindingId`;
- имеет неположительный `repeatNumber`;
- содержит неизвестную роль;
- повторяет ключ `experiment + repeat + role`;
- указывает на отсутствующий resource;
- использует не `GuidedExperiment` как experiment resource;
- использует не `Trace` как target resource.

При удалении `GuidedExperiment` или `Trace` resource все persistent bindings,
которые на него ссылались, автоматически удаляются из manifest. Исходные файлы
при этом не удаляются и не изменяются.

## Экран `Целостность…`

В верхней панели CraneCAN доступна кнопка `Целостность…`.

Проверка показывает ERROR / WARNING / INFO и отдельно проверяет:

- внутреннюю структуру `.canproject`;
- существование всех resources;
- существование active profile / active experiment;
- существование Trace, используемых persistent bindings;
- читаемость `*.canexperiment`;
- повторяющиеся или неположительные RepeatNumber;
- stale persistent bindings, для которых в experiment больше нет соответствующей
  REFERENCE / ACTION / RETURN зависимости;
- unbound TRC dependencies;
- однозначное автоматическое разрешение через Trace resource;
- неоднозначные одинаковые имена Trace;
- отсутствующие TRC;
- TRC, которые существуют внутри папки проекта, но не зарегистрированы как
  Trace resource;
- зависимости на файл вне папки проекта, которые делают проект непереносимым.

## Интерпретация

`ERROR` означает, что зависимость не может быть однозначно использована либо
ключевая часть проекта отсутствует/некорректна. Перед полевой работой такую
ошибку следует устранить.

`WARNING` означает, что проект может работать на текущем ПК, но полнота или
переносимость не гарантируется. Типичный пример — TRC существует только по
абсолютному пути вне папки проекта.

`INFO` фиксирует корректные persistent bindings и однозначные автоматические
разрешения. Если ERROR и WARNING отсутствуют, экран показывает состояние `OK`.

## Persistent binding остаётся авторитетным

Если зависимость имеет explicit persistent binding, Project Integrity не ищет
замену по имени. Если bound Trace отсутствует, это ERROR. Такое поведение
предотвращает молчаливую загрузку другого `capture.trc`.

## Что проверка не делает

Project Integrity не изменяет `*.canexperiment`, `*.trc`, Machine Profile,
incident или другие исходные материалы. Она также не доказывает физическую
причинность CAN-сигнала и не является проверкой конфигурации ECU.

Архитектура CraneCAN остаётся receive-only / LISTEN ONLY; данный этап не добавляет
CAN transmit API.
