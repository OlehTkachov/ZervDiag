# DBC / J1939 import — CraneCAN 0.7

## Назначение

Этап добавляет в CraneCAN документированную CAN-базу как ещё один источник
evidence. Кнопка `Импорт DBC…` находится в блоке Machine Profile.

Импорт полностью offline/read-only относительно CAN-шины. CAN Tx отсутствует.

## Что поддерживается в DBC

CraneCAN разбирает основные конструкции:

- `BO_` — сообщение, CAN ID, DLC, sender;
- `SG_` — start bit, bit length, Intel/Motorola, signed/unsigned,
  factor, offset, min/max, unit, receivers;
- `CM_ SG_` — комментарий сигнала;
- `VAL_` — enum/state table;
- `SIG_VALTYPE_` — определение float/double;
- `BA_ "SPN" SG_` — J1939 SPN;
- `BA_ "VFrameFormat" BO_` и соответствующий `BA_DEF_` — J1939PG;
- global `BA_ "ProtocolType" "J1939"`.

Vector DBC extended ID декодируется из marker bit 31. Для совместимости
принимается и bare 29-bit ID `0x00000800…0x1FFFFFFF`, но создаётся warning.

## ByteOrder

DBC `@1` импортируется как `LittleEndian`.

DBC `@0` импортируется как `BigEndian` по уже зафиксированной
DBC/Motorola sawtooth convention:

- `StartByte/StartBit` указывает MSB;
- внутри байта биты идут к bit 0;
- затем продолжаются с bit 7 следующего DATA-байта.

Это позволяет использовать DBC start bit без скрытого преобразования.

## Ограничения импорта

Текущий Machine Profile предназначен для Classical CAN integer signals.

Поэтому автоматически не импортируются:

- сообщения с DLC > 8 (CAN FD);
- conditional multiplexed signals `m0`, `m1`, …;
- `SIG_VALTYPE_` Float32/Float64;
- поля, выходящие за `DATA[0…7]`;
- определения с некорректным factor/offset/bit geometry.

Сам multiplexor `M` может быть импортирован как обычное integer поле.
Conditional multiplex decoding будет отдельным этапом.

## Политика Machine Profile

Новый DBC/J1939 signal создаётся как `PROBABLE`, но **никогда не
`CONFIRMED` автоматически**.

Для нового сигнала сохраняются:

- CAN ID и Standard/Extended;
- bit geometry;
- ByteOrder;
- signed/unsigned;
- scale / offset / unit;
- enum states;
- DBC comment;
- portable source name;
- evidence kind `Dbc` либо `J1939Database`.

Absolute local path в `SourceReference`, `Source` и evidence description
не сохраняется.

Если в Machine Profile уже существует то же поле:

- при совпадающей engineering semantics добавляется только новое evidence;
- существующий confidence не повышается автоматически;
- одинаковое evidence повторно не добавляется;
- при различии ByteOrder/signed/scale/offset/unit существующий signal не
  перезаписывается, а импорт выдаёт conflict warning.

## J1939 29-bit ID

`J1939IdentifierCodec` разбирает:

- Priority;
- Extended Data Page;
- Data Page;
- PDU Format;
- PDU Specific;
- Source Address;
- PGN;
- Destination Address для PDU1.

PGN формируется по J1939:

- для PDU1 (`PF < 240`) PS является destination address, поэтому младший
  байт PGN равен 0;
- для PDU2 (`PF >= 240`) PS входит в PGN.

Пример:

```text
ID 0x18F004AB
Priority = 6
PGN = 0x0F004 (61444)
SA = 0xAB
```

Пример PDU1:

```text
ID 0x18EAFF3D
Priority = 6
PGN = 0x0EA00 (59904)
DA = 0xFF
SA = 0x3D
```

## SPN decode

Если DBC сообщает J1939 PGN/SPN, MachineSignal получает:

- `Protocol = "J1939"`;
- `J1939Pgn`;
- `J1939Spn`.

`J1939SignalDecoder` может декодировать полученный 29-bit Rx frame через
обычный `MachineSignalDecoder`, сохраняя raw и engineering value.

Для PDU2 разрешается изменение Source Address при том же PGN.
Для PDU1 Source Address также может отличаться, но Destination Address должен
совпадать с DBC template. Это предотвращает автоматическое смешивание
destination-specific сообщений.

Пример SPN 190 Engine Speed:

```text
DBC signal:
StartBit=24
Length=16
@1
Factor=0.125
PGN=0x0F004
SPN=190

DATA[3..4] = 40 1F
raw = 8000
engineering = 1000 rpm
```

## Evidence и инженерная осторожность

DBC/J1939 database является независимым документированным источником, но файл
может относиться к другой версии ECU/машины. Поэтому импорт не доказывает, что
конкретный кран использует именно эту версию базы.

Для `CONFIRMED` всё ещё требуется явная инженерная проверка:
схема/документация нужной версии, физический эксперимент, измерение либо другое
трассируемое evidence.

Поддержка DBC/J1939 не открывает transmit API и не меняет LISTEN ONLY
архитектуру CraneCAN.
