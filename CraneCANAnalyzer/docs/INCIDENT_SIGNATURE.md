# Cross-Incident Repeatability / Signature — CraneCAN 0.7

## Назначение

Режим `Повторяемость 3+ incident…` ищет CAN-события, которые повторяются
в нескольких независимых `*.canincident`.

Текущий открытый incident используется как первое повторение. Пользователь
выбирает минимум два дополнительных файла, то есть рабочая серия содержит
не менее трёх incident.

Функция полностью offline и не содержит CAN Tx.

## Подготовка каждого incident

Для каждой записи независимо выполняются уже существующие этапы:

1. `Incident First Changes`;
2. выравнивание по самому раннему marker = `0.000 s`;
3. `Observed Incident Event Chain`;
4. аннотация текущим Machine Profile.

После этого шаги объединяются только по точному ключу:

`CAN ID + Standard/Extended + DATA[n] + тип события`.

Standard и Extended ID с одинаковым числом никогда не объединяются.

## Что измеряется

Для каждого уникального шага сохраняются:

- число incident, где он наблюдался;
- repeatability `%`;
- median времени относительно marker;
- минимальное/максимальное время;
- полный разброс времени;
- модальный `baseline → observed`;
- согласие перехода;
- число повторений, где шаг был отмечен как `кандидат на разрыв`;
- имена пересекающихся сигналов Machine Profile.

Одноразовые события не скрываются: они остаются видимыми как INFO.

## Ranking

### HIGH

HIGH присваивается только если одновременно выполнено:

- серия содержит минимум 3 incident;
- шаг наблюдался во всех incident;
- `baseline → observed` совпал во всех повторениях;
- разброс времени относительно marker не больше `250 ms`;
- ни одно повторение этого шага не было только INFO-evidence.

HIGH означает сильную повторяемость наблюдаемого CAN-события, но не
доказанную физическую причинность.

### MEDIUM

MEDIUM присваивается, когда:

- шаг наблюдался минимум два раза;
- присутствует минимум в `2/3` выбранных incident;
- модальный переход совпадает минимум в `2/3` наблюдений этого шага;
- есть хотя бы одно не-INFO наблюдение.

Большой разброс времени не скрывается и остаётся видимым в отдельной колонке.

### INFO

INFO используется для:

- одноразовых событий;
- повторяемости ниже `2/3`;
- слабого согласия перехода;
- событий, которые во всех повторениях имели только INFO-evidence.

## Проверки качества

Режим явно предупреждает о:

- разных `CAN channel` metadata;
- разных известных bitrate;
- неизвестном bitrate в части серии;
- смешивании replay/live capture origin;
- разных driver metadata;
- неполных incident;
- разных подписях marker;
- предупреждениях качества, пришедших из каждого Event Chain.

Копии одного и того же Incident ID нельзя использовать как независимые
повторения.

## Диагностический смысл

Сигнатура нужна для отделения устойчивого предвестника от случайного CAN-шумa.

Пример:

`-0.150 s  Joystick command   3/3`
`+0.040 s  Enable             3/3`
`+0.110 s  Valve command      3/3`
`+0.420 s  periodic ID stop   3/3`

Если одна и та же последовательность повторяется в нескольких отказах, она
полезнее одиночного incident. Однако даже стабильная `3/3` сигнатура не
означает автоматически, что последний или первый узел физически неисправен.

Для вывода о причине нужны независимые evidence: GOOD/FAULT comparison,
электросхема, повторяемый эксперимент, Machine Profile, измерение напряжения/
тока или физическая проверка исполнительного механизма.
