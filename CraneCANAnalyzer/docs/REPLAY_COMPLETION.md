# Replay: проверка длительности и конец TRC

Перед запуском Guided Experiment проверяется хронологический порядок TRC,
наличие принимаемых кадров Classical CAN и доступная длительность от первого
до последнего кадра. Требуется сумма REFERENCE + ожидание + ACTION + POST.
Для настроек 5 + 3 + 10 + 5 нужна запись минимум 23 секунды;
для ACTION = 30 нужно 43 секунды. При отказе прежние результаты сохраняются,
новый raw capture не создаётся. Проверка длительности не заменяет проверку
качества окон анализатором: длительная запись всё ещё может быть разреженной.

Обычный EOF Replay не является ошибкой адаптера. Если опыт не успел закончиться,
он остаётся INVALID/ABORTED с кодом ReplayExhausted. Активное окно события
сохраняется неполным с POST_INTERRUPTED и REPLAY_ENDED. Сам EOF не добавляет
CAPTURE_UNCERTAIN; настоящие ошибки/потери продолжают влиять на качество.
Конец TRC не мешает повторно запустить Replay. Двойное нажатие START и
отключение во время предварительного чтения заблокированы.

Проверки: стандартная 23-секундная запись, недостаточная длительность,
пустой TRC, только Tx, нарушенная хронология, сдвиг абсолютного времени,
EOF завершённого/незавершённого опыта, поздняя отметка события.
Существующие проверки потери соединения и SOOSAN остаются в общем smoke suite.

Предварительная проверка читает TRC построчно без накопления кадров, в фоне.
Строка состояния показывает процент прочитанных байтов (приблизительно из-за
буферизации) и число кадров. ABORT / STOP отменяет подготовку; прежние результаты
сохраняются, новый опыт и raw capture не создаются. Закрытие окна отменяет проверку.

Replay выдаёт кадры построчно через тот же парсер, без списка всей трассы.
Ограничение в миллион кадров снято именно для Replay; обычный импорт в таблицу
сохраняет прежний защитный лимит. Первичная проверка и воспроизведение читают
файл отдельно. Повторный запуск открывает файл заново с начала.
Закрытие прерывает ожидание времени/шага; новый запуск возможен после завершения
предыдущего перечислителя. Порядок, timestamps, каналы, Std/Ext и DATA сохраняются.

Ограничения: потоковое чтение не ограничивает память других потребителей:
окна эксперимента и анализ по-прежнему сохраняют свои кадры. Длина отдельной
строки также влияет на память. Это не гарантия ограниченной памяти всего приложения.
Индикатор показывает время по последнему
принятому кадру и учитывает остановку Replay в конце POST, даже если TRC длиннее. Отметка слишком позднего события допустима,
но запись явно обозначается как неполная. Новых функций передачи CAN нет.


Подсказки интерфейса обновляются для REFERENCE, ожидания, ACTION, POST и анализа.
Итоговый результат и причины отказа сохраняются. После остановки приёма больше
не предлагается накапливать предысторию. До первого кадра отметка недоступна.
При короткой предыстории или остатке менее пяти секунд показано предупреждение;
оператор может сохранить неполную запись. Наличие времени не означает достаточное
качество кадров или подтверждение функции машины.


Проверки потокового чтения: совпадение времён/числа кадров/счётчиков пропусков
с обычным импортом доступных TRC fixtures; пустая запись; более двух миллионов
кадров; монотонный прогресс 0–100%; отмена после начала чтения и освобождение файла.
Core, PCAN и smoke suite собраны прямым вызовом Roslyn SDK 8.0.424; suite пройден.
Полная WPF-сборка и проверка кнопки отмены в Windows остаются проверкой установки.


Потоковый Replay проверен на 2 000 001 кадре, повторном открытии с начала,
закрытии во время ожидания Step и совпадении кадров с обычным импортом fixtures.
Существующие тесты Live Receiver, ONK, Generic, SOOSAN и отмены чтения сохранены.


### Русские этапы и пояснение Replay

BASELINE отображается как «ИСХОДНОЕ СОСТОЯНИЕ», ACTION — «ДЕЙСТВИЕ»,
POSTACTION — «ПОСЛЕ ДЕЙСТВИЯ», COMPLETED — «ЗАВЕРШЕНО».
Новые строки вынесены в Resources/LiveStrings.resx на уровне приложения;
внутренние enum и форматы сохранения не переименованы. Это начало локализации,
а не полный перевод экспертного интерфейса.

Во время Replay инструкции описывают чтение участка файла, без предложения
выполнять действие на машине. Постоянная подсказка поясняет: имя действия задано
оператором, соответствие временному участку нужно установить по исходной записи;
повторное воспроизведение файла не является независимым физическим опытом.
Подсказка не меняет алгоритм score и не подтверждает физический смысл кандидатов.
