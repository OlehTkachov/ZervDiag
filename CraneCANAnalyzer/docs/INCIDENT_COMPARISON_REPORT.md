# Portable GOOD/FAULT Incident Report — CraneCAN 0.7

## Назначение

После `GOOD/FAULT Incident Chain Comparison` результат можно сохранить кнопкой
`Сохранить отчёт…`.

Формат отчёта — Markdown (`*.md`, также разрешён `*.txt`). Он рассчитан на:

- передачу другому инженеру;
- прикрепление к следующему сеансу диагностики;
- архивирование вместе с `.canincident`;
- последующий анализ человеком или ИИ без обязательного запуска CraneCAN.

Функция полностью offline и не содержит CAN Tx.

## Что входит в отчёт

Отчёт содержит:

- имена двух `.canincident`;
- Incident ID;
- capture origin;
- driver/channel;
- bitrate metadata;
- состояние LISTEN ONLY metadata;
- полноту и quality codes;
- число кадров и markers;
- длительность окон;
- текущий Machine Profile и его идентификатор;
- количество HIGH/MEDIUM/INFO;
- первое наблюдаемое расхождение;
- все warnings;
- полную таблицу различий GOOD/FAULT.

Для каждого различия сохраняются ID, Standard/Extended, DATA[n], тип события,
Profile signal, времена относительно marker, `Δt`, GOOD/FAULT transition и
описание.

## Переносимость и приватность

В отчёт намеренно не записываются абсолютные локальные пути к `.canincident`
или `capture.trc`. Сохраняются только имена файлов `.canincident`.

Это позволяет передавать отчёт между компьютерами без утечки структуры
локальных каталогов и без ложной зависимости от диска `C:`/`D:`.

Текст Markdown экранирует `|` и переносы строк внутри таблиц.

## Ограничение

Отчёт фиксирует результат алгоритмов на момент сохранения. Он не является
дампом конфигурации ECU и не доказывает причинность.

Первое расхождение между GOOD и FAULT нужно подтверждать повторяемостью,
Machine Profile evidence, схемой и независимыми измерениями.
