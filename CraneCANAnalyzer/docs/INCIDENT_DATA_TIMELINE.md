# Incident DATA Timeline — CraneCAN 0.7

## Назначение

`График DATA-шаг…` визуализирует raw значение выбранного `DATA[n]`
из `Incident Event Chain` относительно marker сохранённого `*.canincident`.

Функция полностью offline и не содержит CAN Tx.

## Что отображается

Для выбранного шага `байт изменился` CraneCAN берёт только:

- Classical CAN;
- Rx;
- тот же numeric CAN ID;
- тот же Standard/Extended формат;
- кадры без RTR/error;
- кадры, в которых существует выбранный `DATA[n]`.

Ось X — время относительно marker, `0.000 s` отмечено отдельной вертикальной
линией. Второй вертикальной линией отмечается время transition-кандидата,
которое рассчитано `Incident First Changes`.

Ось Y — raw байт `0…255`. В этой версии график намеренно не применяет
`scale/offset` из Machine Profile: это позволяет видеть исходное CAN evidence
без скрытой инженерной интерпретации.

## Большие записи

Если для одного ID накоплено больше 3000 точек, визуализация сокращается.
Алгоритм сохраняет:

- первый и последний отсчёт;
- локальные минимумы;
- локальные максимумы временных блоков.

Поэтому короткий выброс имеет больше шансов остаться видимым, чем при простом
выборе каждого N-го кадра. При downsampling программа явно показывает
предупреждение.

Исходные CAN-кадры внутри `.canincident` при этом не изменяются.

## Ограничение интерпретации

График полезен для различения:

- дискретного переключения;
- ступенчатой последовательности;
- ramp/аналогоподобного поведения;
- дрожания и transient;
- изменения, которое началось до marker.

Но форма графика сама по себе не доказывает, что байт является датчиком,
джойстиком, клапаном или физической причиной отказа. Для этого используются
Machine Profile evidence, повторяемые эксперименты, схема и измерения.
