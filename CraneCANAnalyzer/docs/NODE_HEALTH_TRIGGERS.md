# Node Health automatic trigger — CraneCAN 0.7

## Назначение

Node Health работает только по пассивно принимаемым Classical CAN Rx-кадрам.
Он учится периодичности каждого `(CAN ID, Standard/Extended)` и может
автоматически поставить отметку Pre-Fault Recorder, если ранее стабильный
периодический ID перестал приходить.

Термин `Node` здесь условный: один CAN ID не обязательно равен одному
физическому ECU. CraneCAN не объявляет контроллер неисправным только из-за
этого события.

## Защита от ложных trigger

По умолчанию ID не считается периодическим, пока:

- накоплено не менее 8 интервалов;
- наблюдение длится не менее 10 секунд;
- медианный период не превышает 1 секунду;
- разброс p90/p10 не превышает 2.5.

Timeout рассчитывается как `5 × median period`, но ограничен диапазоном
250 мс … 5 с. Один timeout выдаётся только один раз до восстановления ID.

Короткие event-driven bursts не должны вооружать Node Health только потому,
что внутри burst кадры шли регулярно.

## Автоматическая запись

На вкладке LIVE GUIDED есть флажок:

`Авто-триггер: пропажа периодического CAN ID`

По умолчанию он выключен. При включении timeout запускает тот же
Pre-Fault Recorder `−10 / +5 с`, что и ручная отметка. Передача CAN не
используется.

История Pre-Fault Recorder хранится 15 секунд (`pre + post`), чтобы недавний
автоматический trigger мог получить полную 10-секундную предысторию даже при
небольшой задержке обнаружения.

Если предыдущий incident ещё не сохранён, новый автоматический incident не
запускается — существующее evidence не перезаписывается. Несколько timeout,
попавших в одно активное окно, сохраняются как несколько отметок без
расширения окна.

## Replay и реальный PCAN

Для Replay timeout проверяется по timestamps самой записи при поступлении
следующего кадра. Для реального PCAN дополнительно используется wall-clock
проверка, поэтому полное молчание шины также может быть замечено после
обучения Node Health.

Node Health не заменяет счётчики bus errors/lost frames и не определяет
причину пропадания сообщения. Его результат — только наблюдаемое событие,
которое удобно сохранить для дальнейшего GOOD/FAULT анализа.
