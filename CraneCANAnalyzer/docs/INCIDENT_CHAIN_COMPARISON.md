# GOOD/FAULT Incident Chain Comparison — CraneCAN 0.7

## Назначение

Режим сравнивает два сохранённых `*.canincident` после того, как каждая запись
независимо выровнена по своему самому раннему marker = `0.000 s`.

Текущий открытый incident используется как `ЭТАЛОН / GOOD / BEFORE`, а второй
выбранный файл как `СРАВНЕНИЕ / FAULT / AFTER`.

Функция полностью offline и не содержит CAN Tx.

## Что сравнивается

Для каждой записи CraneCAN выполняет существующие этапы:

1. `Incident First Changes`;
2. `Observed Incident Event Chain`;
3. сопоставление шагов по точному ключу:
   `CAN ID + Standard/Extended + DATA[n] + тип события`.

После этого показываются:

- шаг только в GOOD;
- шаг только в FAULT;
- другой `baseline → observed` для того же шага;
- изменение времени шага относительно marker;
- изменение вычисляемого признака `кандидат на разрыв`.

Standard и Extended ID с одинаковым числом никогда не объединяются.

## Тайминг

По умолчанию разница времени менее `100 ms` не выводится.

`100…499 ms` — INFO.

`500 ms` и больше — MEDIUM.

Изменение только тайминга намеренно не получает HIGH, потому что задержка
может зависеть от действий оператора, нагрузки, частоты сообщений и качества
marker.

## Проверки качества

UI предупреждает, если отличаются CAN channel, bitrate metadata, capture
origin или полнота incident. Также переносятся предупреждения Incident First
Changes и Event Chain.

## Ограничение интерпретации

Первое различие между GOOD и FAULT — это место, где две наблюдаемые
CAN-последовательности перестали совпадать по используемым критериям.

Это не означает автоматически, что найден физически неисправный ECU, датчик,
клапан или провод. Различие следует подтверждать повторным экспериментом,
Machine Profile evidence, схемой и электрическими/гидравлическими измерениями.
