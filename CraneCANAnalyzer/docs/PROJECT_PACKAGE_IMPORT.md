# CraneCAN — импорт и проверка переносимого Project Package

## Назначение

`Импорт ZIP…` открывает переносимый CraneCAN package без ручной распаковки. Импорт считается успешным только после проверки структуры ZIP, содержимого `.canproject`, всех зарегистрированных resources и Project Integrity уже распакованной копии.

Импорт не выполняет CAN I/O и не добавляет передачу CAN. Это полностью офлайн-операция с файлами.

## Последовательность

1. Инженер выбирает ZIP package.
2. Выбирает родительскую папку для импорта.
3. CraneCAN создаёт имя новой папки из имени ZIP.
4. Если такая папка уже существует, импорт останавливается. Существующие материалы не перезаписываются.
5. ZIP сначала анализируется без публикации файлов проекта.
6. Допускается ровно один `.canproject` в корне архива.
7. Состав файлов ZIP должен точно совпадать с manifest: `.canproject` + зарегистрированные resources. Лишние и отсутствующие файлы блокируют импорт.
8. Файлы извлекаются в приватную временную папку рядом с конечным каталогом.
9. Каждый entry хешируется SHA-256 во время распаковки; фактический размер сверяется с ZIP metadata.
10. На временной копии выполняется Project Integrity.
11. Только после успешных проверок временная папка атомарно переименовывается в конечную папку проекта.
12. Импортированный `.canproject` сразу открывается в CraneCAN.

## Защита путей

Импортер не использует слепой `ExtractToDirectory` для недоверенного архива. Каждый путь нормализуется и проверяется до создания файла.

Блокируются:

- `../` и `.` сегменты;
- абсолютные пути;
- drive-qualified пути (`C:` и аналогичные);
- пустые сегменты и NUL;
- Windows ADS через `:`;
- недопустимые Windows-символы;
- имена, заканчивающиеся точкой или пробелом;
- зарезервированные Windows device names (`CON`, `NUL`, `COM1`, `LPT1` и т. п.);
- symbolic links в ZIP;
- одинаковые пути с различием только в регистре;
- конфликт, когда один путь одновременно используется как файл и каталог.

## Ограничения размера

Для защиты от явно повреждённых/враждебных архивов действуют высокие технические пределы, не мешающие обычным большим CAN-трассам:

- до 20 000 файлов;
- до 128 GiB на один файл;
- до 256 GiB суммарного распакованного объёма.

Перед распаковкой CraneCAN по возможности проверяет доступное свободное место на целевом диске.

## Проверка SHA-256

После выбора ZIP CraneCAN вычисляет SHA-256 самого архива. Этот SHA-256 выводится после успешного импорта и может быть сравнен с SHA-256, который был показан при `Экспорт ZIP…` на исходном компьютере.

Для каждого ZIP entry SHA-256 вычисляется во время фактической распаковки. Это позволяет обнаружить ошибки чтения/распаковки и сохранить проверяемый fingerprint каждого файла в результате операции.

ZIP format сам по себе не является цифровой подписью. Совпадение SHA-256 с заранее переданным доверенным значением подтверждает совпадение байтов архива, но не доказывает происхождение package без отдельной доверенной подписи/канала передачи hash.

## Строгое соответствие manifest

Package должен содержать только:

- один корневой `.canproject`;
- resources, перечисленные в этом `.canproject`.

Незарегистрированные файлы не принимаются. Зарегистрированный, но отсутствующий resource также блокирует импорт.

Persistent TRC bindings сохраняются через Resource ID. После переноса папки они продолжают указывать на соответствующие Trace resources при условии успешного Project Integrity.

## Поведение при ошибке

До завершения всех проверок конечная папка проекта не публикуется. При ошибке временная папка удаляется по best-effort правилу. Существующие каталоги и файлы пользователя не удаляются и не перезаписываются.

## Полевая рекомендация

Для передачи проекта между компьютерами:

1. На исходном ПК выполнить `Целостность…`.
2. Выполнить `Экспорт ZIP…` и сохранить показанный SHA-256.
3. Передать ZIP и SHA-256 по независимому/доверенному каналу, если требуется контроль целостности передачи.
4. На целевом ПК выполнить `Импорт ZIP…`.
5. Сравнить SHA-256 импорта с исходным SHA-256.
6. Перед работой на машине снова выполнить `Целостность…`.

CraneCAN остаётся receive-only/listen-only в CAN-части; импорт package не передаёт CAN-сообщений.
