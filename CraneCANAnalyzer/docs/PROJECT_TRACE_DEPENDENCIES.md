# CraneCAN — project-aware TRC dependencies

## Проблема

Старые `*.canexperiment` могут содержать абсолютные пути к исходным `*.trc`.
После копирования папки проекта на другой компьютер такой путь больше не
существует, хотя нужная трасса уже находится внутри `*.canproject` как resource
типа `Trace`.

## Поведение 0.7

При загрузке `*.canexperiment` CraneCAN запоминает путь самого эксперимента.
Когда `GuidedExperimentRunLoader` открывает REFERENCE / ACTION / RETURN TRC,
он сначала ищет `*.canproject`, которому принадлежит этот experiment resource.

Если проект найден, Trace resource внутри проекта имеет приоритет над старым
абсолютным путём. Благодаря этому папку проекта можно перенести на другой ПК без
редактирования исходного `*.canexperiment`.

Порядок разрешения зависимости:

1. найти `*.canproject`, в котором текущий `*.canexperiment` зарегистрирован как
   `GuidedExperiment` resource;
2. попытаться найти точное совпадение Trace resource по пути;
3. если точного совпадения нет — использовать совпадение по имени файла только
   когда оно единственное;
4. если проектной привязки нет, сохранить прежнее поведение: существующий
   абсолютный путь или путь относительно каталога `*.canexperiment`;
5. если несколько project Trace имеют одинаково подходящее имя, не угадывать —
   остановить загрузку и показать кандидатов.

## Важные ограничения

- Исходный `*.canexperiment` не переписывается.
- `*.trc` не копируется, не переименовывается и не изменяется.
- Автоматическая привязка разрешает только Trace resources, уже находящиеся
  внутри папки проекта и прошедшие правила `*.canproject`.
- При неоднозначности CraneCAN намеренно не выбирает файл автоматически.
- Абсолютный legacy path не переносится в `*.canproject` самим механизмом
  rebinding.

## Рекомендуемая структура

```text
SOOSAN_JK1200A/
  SOOSAN_JK1200A.canproject
  experiments/
    TELESCOPE_OUT.canexperiment
  traces/
    telescope_out.trc
```

После переноса всей папки, например с `D:\field\SOOSAN_JK1200A` на
`C:\Diagnostics\SOOSAN_JK1200A`, experiment остаётся прежним, а фактический TRC
разрешается через относительный Trace resource проекта.

Если в проекте есть несколько файлов с одинаковым именем `capture.trc`, лучше
использовать уникальные имена трасс либо хранить в `*.canexperiment` относительный
путь, однозначно совпадающий с resource проекта.

## Безопасность

Механизм работает только на чтение сохранённых файлов. Он не добавляет CAN Tx и
не меняет LISTEN ONLY архитектуру CraneCAN.
