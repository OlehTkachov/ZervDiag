# Observed Event Chain — CraneCAN 0.7

## Назначение

`Цепочка событий` строится из результата `Incident First Changes`.
Шаги сортируются строго по наблюдаемому времени относительно marker.

Функция полностью offline и не содержит CAN Tx.

## Аннотация Machine Profile

Для каждого шага CraneCAN пытается найти известные или экспериментальные
сигналы текущего Machine Profile с тем же Standard/Extended CAN ID.

Для изменения `DATA[n]` сигнал считается пересекающимся только если его
битовое поле действительно затрагивает этот байт. Поэтому Standard и Extended
ID с одинаковым числом не смешиваются, а многобайтные сигналы могут
аннотировать несколько DATA-байтов.

Название `Joystick command`, `Enable`, `Valve` и т.п. появляется только если
оно уже записано пользователем/экспериментом в Machine Profile. CraneCAN не
угадывает физическое назначение неизвестного ID по порядку сообщений.

## Кандидаты на разрыв

Шаг отмечается как `Разрыв?`, если наблюдается одно из объективных условий:

- прекратился ранее стабильный периодический CAN ID;
- между двумя соседними событиями с приоритетом HIGH/MEDIUM имеется пауза
  не менее 750 мс.

Это кандидат на место дополнительной проверки, а не доказанный breakpoint
управляющей логики.

Пример наблюдаемой цепочки:

`−0.120 s  Joystick command`
`+0.030 s  неизвестный ID`
`+0.090 s  Enable`
`+0.240 s  Valve command`
`+1.100 s  периодический ID прекратился  ← кандидат на разрыв`

Чтобы утверждать, что ожидаемая цепочка должна быть именно
`Joystick → Enable → Valve`, необходима независимая информация:
схема, документация, несколько повторов эксперимента или подтверждение
сигналов в Machine Profile.

## Практическое применение

Рекомендуется использовать совместно с:

- `Incident First Changes`;
- Node Health;
- GOOD/FAULT First Divergence;
- Configuration Snapshot comparison;
- электрическими и гидравлическими измерениями.

Цель — быстро сузить участок диагностики, сохраняя различие между
наблюдаемой последовательностью и подтверждённой причинностью.
