# Cross-Incident Signature → Machine Profile — CraneCAN 0.7

## Назначение

После анализа `Повторяемость 3+ incident…` инженер может сохранить повторяемый
DATA[n]-кандидат в текущий Machine Profile.

Функция полностью offline и не содержит CAN Tx.

## Какие кандидаты можно добавлять

В профиль допускаются только:

- `ByteChanged`;
- с известным `DATA[n]`;
- приоритет `MEDIUM` или `HIGH`.

`INFO` намеренно блокируется, чтобы единичные и слабые события не загрязняли
Machine Profile.

Пользователь задаёт:

- название;
- StartByte;
- StartBit;
- BitLength;
- byte order;
- signed/unsigned;
- scale;
- offset;
- unit;
- заметки.

Заданное поле обязано пересекать тот DATA[n], который повторяемо изменялся.

## Автоматический статус

### HIGH → PROBABLE

Новый HIGH-кандидат сохраняется как `PROBABLE`, потому что текущий алгоритм
HIGH уже требует:

- минимум 3 независимых incident;
- присутствие шага во всех incident;
- одинаковый переход во всех наблюдениях;
- разброс времени ≤250 ms;
- отсутствие INFO-only повторений.

Если точное битовое поле уже существует как `CANDIDATE`, HIGH evidence может
повысить его до `PROBABLE`.

### MEDIUM → CANDIDATE

MEDIUM сохраняется только как `CANDIDATE`.

### CONFIRMED

Ни HIGH, ни любое количество incident не переводят сигнал автоматически в
`CONFIRMED`. Для CONFIRMED по-прежнему требуется независимое инженерное
подтверждение: физическая проверка, документация, схема, измерение или явное
подтверждение пользователя.

Существующий `CONFIRMED` сигнал никогда не понижается.

## Evidence

Machine Profile получает evidence типа `CrossIncidentSignature`.

Сохраняются:

- repeatability N/M;
- transition agreement;
- модальный baseline → observed;
- median времени относительно marker;
- timing spread;
- отсортированные Incident ID серии.

Абсолютные пути к incident/capture в evidence не сохраняются.

Если одна и та же серия Incident ID добавляется повторно в другом порядке,
evidence не дублируется.

## Ограничение интерпретации

`PROBABLE` означает хорошо повторяемое наблюдение CAN, а не доказанную
физическую причинность.

Например, стабильный 3/3 байт может быть следствием команды другого ECU,
а не первичной причиной отказа. Для причинного вывода его следует сопоставлять
с GOOD/FAULT comparison, схемой, электрическими/гидравлическими измерениями и
физической реакцией машины.
