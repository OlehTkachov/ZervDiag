# Сравнение Configuration Snapshot — CraneCAN 0.7

## Назначение

Режим сравнивает два ранее сохранённых `*.cansnapshot`.

Рекомендуемый порядок:

1. сохранить snapshot исправной машины или состояния **до** вмешательства;
2. сохранить второй snapshot неисправного состояния или состояния **после** ремонта;
3. нажать `Сравнить снимки…`;
4. первым выбрать эталонный `GOOD / BEFORE`, вторым — `FAULT / AFTER`.

Сравнение полностью offline и не содержит CAN Tx.

## Какие различия показываются

`HIGH`:

- CAN ID появился;
- CAN ID исчез;
- изменился modal DLC;
- устойчиво изменился modal DATA.

`MEDIUM`:

- изменился набор встречавшихся DLC при неизменном modal DLC;
- modal DATA отличается, но изменение недостаточно стабильно;
- средний период изменился не менее чем на 50%;
- изменилась видимость ID, связанного с сигналом того же Machine Profile.

`INFO`:

- средний период изменился на 25–50%.

Период сравнивается только когда в обоих snapshot есть минимум три кадра
соответствующего ID. Изменение тайминга само по себе не считается доказательством
неисправности.

## Проверки совместимости

CraneCAN отдельно предупреждает, если отличаются:

- имя машины;
- CAN bus;
- bitrate, записанный в Machine Profile;
- источник snapshot;
- длительность записей более чем на 25%;
- `ProfileId`.

При разных `ProfileId` видимость profile signals не сравнивается.

## Ограничение интерпретации

Snapshot содержит наблюдаемое состояние CAN-шины, а не внутренний дамп ECU.
Поэтому `ID исчез`, `DATA изменился` или `период изменился` означает только
различие двух наблюдений. Причину необходимо подтверждать схемой,
документацией, независимым экспериментом или физической проверкой.
