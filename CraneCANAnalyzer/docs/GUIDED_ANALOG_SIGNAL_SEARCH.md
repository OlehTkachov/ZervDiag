# Guided Analog Signal Search

## Назначение

`Guided Analog Signal Search` — пассивный поиск raw CAN-полей, которые ведут себя как непрерывный датчик или положение механизма во время Guided REFERENCE/ACTION эксперимента.

Типовые задачи: длина телескопической стрелы, угол, давление, нагрузка, положение цилиндра/секции, аналоговый джойстик и другие плавно меняющиеся величины.

Это **не автоматическое определение физического смысла**. Результат означает только, что raw-поле статистически похоже на повторяемый тренд в заданном эксперименте.

CAN Tx отсутствует. Анализ работает только по уже полученным Rx Classical CAN кадрам.

## Какие поля проверяются

Первая версия намеренно ограничена прозрачными byte-aligned unsigned представлениями:

- `DATA[n]` — U8;
- `DATA[n..n+1]` — U16 LittleEndian;
- `DATA[n..n+1]` — U16 BigEndian.

Для U16 BigEndian при переносе кандидата в Machine Profile используется уже принятая в CraneCAN DBC/Motorola sawtooth-конвенция: byte-aligned 16-bit поле начинается с `StartBit = 7`.

Signedness, Scale, Offset и Unit не угадываются.

## Что измеряется для каждого повтора

Для каждого raw-поля отдельно считаются median REFERENCE, robust reference noise на основе MAD и 5–95 percentile range, median начала и конца ACTION, сдвиг относительно baseline, ACTION span, направление роста/падения, монотонность с deadband, Pearson correlation raw value с временем внутри ACTION, response/noise, скорость raw units/s, число различных ACTION-значений, доля конечного плато/возможного насыщения, reaction time относительно approximate action time и возврат к baseline при наличии RETURN.

`corr(time)` — только временной proxy. Высокая корреляция не доказывает, что действие оператора физически вызывает изменение этого поля.

## Минимальный gate sensor-like кандидата

Один repeat учитывается только если REFERENCE содержит минимум 4 samples, ACTION минимум 6 samples, в ACTION есть минимум 5 различных raw значений, endpoint shift не меньше `max(4 raw units, 3 × reference noise)`, а monotonicity ≥ 60% **или** `|corr(time)| ≥ 0.60`.

Это специально исключает обычные двухпозиционные `0/1`, `0/255` команды и большую часть хаотического шума.

## Повторяемость и ranking

Повторы группируются по `CAN ID + Standard/Extended + StartByte + Encoding`. Направление должно совпадать. Если два опыта показывают рост, а третий — падение, repeatability становится `2/3`; такой кандидат не может получить HIGH.

HIGH требует одновременно минимум 3 repeat, одинаковое направление во всех repeat, score ≥ 70, median monotonicity ≥ 75% и median `|corr(time)| ≥ 0.70`. MEDIUM допускает менее полную, но всё ещё заметную повторяемость. LOW оставляется для инженерного просмотра.

Score также учитывает response/noise, количество промежуточных значений, реакцию около действия, RETURN и длинное конечное плато.

## Интерфейс

В разделе Guided Diagnostics рядом с `3. АНАЛИЗИРОВАТЬ` появляется кнопка `Аналоговые сигналы…`.

Результат показывает priority, score, CAN ID/format, raw field/endian, направление, repeatability, baseline shift, ACTION span, reference noise, response/noise, monotonicity, `|corr(time)|`, raw rate/s, reaction, plateau, return-to-baseline и причины score.

## Добавление в Machine Profile

Кнопка `Добавить raw-кандидат в профиль` создаёт только `CANDIDATE`.

Автоматически устанавливаются raw unsigned, найденная длина 8/16 bit, найденный byte order, `Scale = 1`, `Offset = 0`, `Unit = ""` и evidence `RepeatedExperiment`.

Не устанавливаются автоматически название физического датчика, signedness, инженерный коэффициент, offset, unit и статус PROBABLE/CONFIRMED. Если такое exact raw-поле уже существует в Machine Profile, существующее определение не перезаписывается.

Evidence не содержит абсолютных TRC-path: сохраняется Experiment ID и переносимый source reference.

## J1939

На этом этапе Extended CAN поля группируются по **точному 29-bit ID**. Это сделано консервативно, чтобы не объединять неизвестные Extended-протоколы как J1939 без доказательств.

Если один J1939 PGN приходит с меняющимся Source Address, используйте J1939 PGN-normalized инструменты CraneCAN. Отдельный PGN-aware Analog Search может быть добавлен следующим этапом.

## Ограничения

По одному experiment нельзя утверждать, что найденный raw-счётчик является длиной, углом или давлением. Для назначения физического смысла нужны дополнительные evidence: повторные управляемые опыты, известные контрольные положения, измерение реального параметра, DBC/J1939, схема/документация или независимая физическая проверка.

Для датчика длины практический следующий шаг — провести несколько безопасных перемещений между известными механическими положениями и проверить линейность raw field относительно реальной длины. Только после этого назначать Scale/Offset/Unit.
