# Machine Profile Confidence / Evidence — CraneCAN 0.7

## Назначение

Новый экран `Machine Profile Confidence / Evidence` отвечает на практический вопрос:

> Почему этот сигнал сейчас имеет статус CANDIDATE / PROBABLE / CONFIRMED и чего не хватает для следующего уровня?

Экран является read-only объяснением. Он не пересчитывает, не повышает и не понижает сохранённый `Confidence` автоматически.

## Где открыть

В блоке `Профиль машины` после загрузки главного окна добавляется кнопка `Evidence…`.

Если профиль пока пустой, CraneCAN сообщает, что сначала нужно добавить сигнал из Guided Diagnostics или Cross-Incident Signature.

## Что показывает таблица

Для каждого Known / Experimental signal:

- текущий статус;
- имя;
- CAN ID и Standard / Extended;
- DATA-поле;
- количество evidence;
- наличие Cross-Incident Signature;
- наличие независимого evidence;
- наличие явного `UserConfirmation`;
- число предупреждений;
- сохранённый Source.

## Что означает «независимое evidence»

К независимым от самой CAN-корреляции источникам относятся:

- электрическая схема;
- гидравлическая схема;
- документация производителя;
- DBC;
- J1939 database;
- конфигурация контроллера;
- MPF;
- сервисное ПО;
- измерение мультиметром;
- измерение тока;
- физическая проверка выхода.

`RepeatedExperiment`, `IncidentCapture` и `CrossIncidentSignature` считаются наблюдаемыми CAN-evidence. Они полезны для повторяемости, но сами по себе не доказывают физическую причинность.

`UserConfirmation` фиксирует явное инженерное решение и трассируемость статуса, но не подменяет схему/документацию/измерение.

## Replay

Если все evidence у сигнала относятся только к Replay, экран формирует отдельное предупреждение:

- Replay подтверждает работу анализа на записи;
- Replay не считается независимым физическим экспериментом на машине.

## CONFIRMED без UserConfirmation

Если профиль содержит `CONFIRMED`, но в evidence отсутствует `UserConfirmation`, CraneCAN не меняет статус сам. Вместо этого он показывает предупреждение, что это может быть импортированный или старый профиль и происхождение `CONFIRMED` необходимо проверить вручную.

## Cross-Incident

Для `CrossIncidentSignature` интерфейс отдельно показывает:

- что повторяемость CAN-шагa действительно сохранена в evidence;
- что повторяемость не равна доказанной физической причинности;
- что для перехода к инженерно подтверждённому назначению желательно независимое evidence.

## Детальная панель

После выбора сигнала показываются:

1. сохранённый статус и геометрия сигнала;
2. текстовое объяснение текущего статуса;
3. сгруппированные evidence с инженерной интерпретацией каждого типа;
4. все исходные evidence с UTC-временем, capture origin, SourceReference и Description;
5. предупреждения качества/трассируемости;
6. рекомендуемые следующие действия для текущего статуса.

## Важное ограничение

Explainer не является автоматическим классификатором исправности ECU и не выводит физическую причинность из порядка CAN-событий.

Он предназначен для прозрачности накопленного Machine Profile knowledge: инженер должен видеть, **какие именно факты сохранены**, **что является CAN-корреляцией**, **что является независимым подтверждением**, и **почему автоматического CONFIRMED не происходит**.

Режим CraneCAN остаётся receive-only / listen-only; CAN Tx в этом функционале отсутствует.
