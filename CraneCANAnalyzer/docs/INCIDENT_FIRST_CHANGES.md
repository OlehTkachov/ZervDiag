# Incident First Changes — CraneCAN 0.7

`Incident First Changes` анализирует сохранённый `*.canincident` относительно самой ранней отметки оператора или автоматического Node Health trigger. Анализ полностью offline и не содержит CAN Tx.

Для стандартного incident `−10 / +5 с` используются `BASELINE −8 … −1 с` и `SEARCH −1 … +4 с`. Поэтому отрицательное время в результате означает изменение непосредственно перед marker.

Кандидаты: появление ID, прекращение ранее периодического ID, изменение DLC и первое изменение DATA-байта относительно baseline. `HIGH` для DATA требует baseline agreement не менее 95% и минимум двух последовательных кадров с новым значением. Однократное изменение не повышается до HIGH.

Исчезновение ID считается только для достаточно регулярного baseline: минимум шесть кадров, медианный период не более 1 с и `p90/p10 <= 2.5`. Момент исчезновения является расчётным timeout, а не измеренным моментом физического отказа.

При нескольких markers анализ привязывается к самому раннему и выдаёт предупреждение. Неполный incident и ограничения качества также переносятся в результат.

Раннее CAN-изменение — кандидат на место начала наблюдаемой цепочки событий, а не доказательство причинности. Результат рекомендуется сопоставлять с Node Health, GOOD/FAULT First Divergence, Configuration Snapshot comparison, схемой и электрическими измерениями.
