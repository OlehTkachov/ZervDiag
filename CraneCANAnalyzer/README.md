# CraneCAN Field — SOOSAN JK1200A

Полевой offline-анализатор трасс PCAN-View для Classical CAN 2.0. Эта редакция
предназначена для испытаний SOOSAN JK1200A и не является сборкой ОНК-160.

> **Безопасность:** в `CraneCAN.Field.exe` отсутствуют live-драйвер и функции
> передачи CAN. Сырой трафик на полигоне записывает PCAN-View в Listen-only,
> CraneCAN открывает уже сохранённый `.trc`.

## Что умеет полевая версия

- импорт PCAN-View `.trc` без изменения порядка кадров;
- Standard 11-bit и Extended 29-bit ID, Rx/Tx, DLC 0–8, timestamp и DATA;
- пропуск комментариев, заголовков, RTR, error/status и неизвестных строк с
  показом диагностики;
- таблица кадров, фильтр по одному или нескольким ID и по формату ID;
- статистика по ID: количество, встречавшиеся DLC, частота и периоды;
- сравнение REFERENCE → ACTION по двум временным окнам одного TRC;
- сравнение отдельных reference/action TRC;
- XOR, переходы отдельных битов, число образцов и устойчивость значений;
- явная фиксация появившихся и исчезнувших сообщений;
- приоритизация устойчивых цифровых изменений и понижение постоянного
  аналогового шума;
- просмотр полного результата и сохранение полного CSV.

Полная HYDAC/J1939-декодировка пока не выполняется: 29-битные ID и все байты
сохраняются в исходном виде, чтобы декодеры можно было добавить позже.

## Перед выездом — обязательная проверка ноутбука

1. Запустить `CraneCAN.Field.exe` из папки публикации.
2. Открыть контрольный `.trc`.
3. Убедиться, что видны Standard и Extended кадры, DLC и DATA.
4. На вкладке `REFERENCE → ACTION` сравнить два окна и сохранить CSV.
5. Запустить PCAN-View и убедиться, что PCAN-USB обнаружен.
6. Проверить переходник и заранее подписать `CAN-H`, `CAN-L`, `GND`.
7. Проверить свободное место и синхронизацию часов ноутбука.
8. Взять копию всей папки публикации и запасной USB-накопитель.

## Настройка PCAN-View на полигоне

| Параметр | Значение |
|---|---|
| Bit rate | `250 kbit/s` |
| Протокол | Classical CAN 2.0 |
| Режим | `Listen-only` |
| Кадры | Standard + Extended |
| Фильтры | полностью открыты |
| Передача | запрещена |
| Дополнительная терминация PCAN | выключена |

Основная точка подключения — `HCH2 / HCL2`. PCAN подключается параллельно
через проверенный переходник; штатное соединение должно сохраняться.

Подробный полевой регламент находится в
[`docs/SOOSAN_FIELD_CAPTURE.md`](docs/SOOSAN_FIELD_CAPTURE.md) и также доступен
на отдельной вкладке программы.

## Контрольная запись понедельника

1. Запустить двигатель и установить `1150–1200 rpm`.
2. Дождаться полной зарядки LPU.
3. Начать запись PCAN-View с открытыми фильтрами.
4. Записать 10–15 секунд спокойного REFERENCE.
5. Задать длину стрелы больше фактической.
6. Отклонить EXTEND примерно на 2–3 секунды.
7. Если движение начинается — вернуть джойстик в нейтраль.
8. Оставить несколько секунд записи после воздействия.
9. Сохранить исходник как `JK1200A_HCH2_engine_1200rpm.trc` и не редактировать.

В CraneCAN открыть файл и задать окна в миллисекундах от начала трассы. Окно
REFERENCE должно содержать только спокойное состояние, ACTION — только
установившееся воздействие. Если окно пустое, программа выдаст понятную ошибку
и не сформирует ложный результат.

## Как читать результат сравнения

- `Очень высокий` — один устойчиво изменившийся бит либо появление/исчезновение ID;
- `Высокий` — устойчивое изменение одного или нескольких байтов;
- `Низкий` — низкая устойчивость, вероятный аналоговый шум;
- `Стабильность R/A` — доля самого частого значения в каждой выборке;
- флажок `Только значимые изменения` скрывает шум только на экране;
- снятие флажка показывает полный результат;
- CSV всегда содержит полный результат, включая неизменившиеся и шумовые строки.

Известный контроль JCH4 для Standard ID `0x18F`:

```text
08 00 00 00 00  →  08 02 C8 00 00
```

Comparator должен показать изменения `DATA[1]` и `DATA[2]`, XOR и переходы
битов. Для HCH2 должны отображаться исходные 29-битные HYDAC ID, в том числе
`0x0CFF5321` (фактический ток Y060/Y061).

## Сборка на Windows

Нужны Windows 10/11 x64 и .NET 8 SDK. Python не нужен.

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\build-windows.ps1
```

Скрипт сначала собирает и запускает все smoke-тесты, включая существующие ONK,
и только после успешных тестов создаёт автономную папку:

```text
publish\soosan-field-win-x64
```

На полевом ноутбуке .NET Runtime не требуется. Переносить нужно всю папку, а
не только EXE.

## Ограничения 0.5.0

- live PCAN-захват не включён: PCAN-View остаётся главным регистратором;
- нет передачи кадров и нет элементов интерфейса для передачи;
- RTR и error/status учитываются в диагностике импорта, но не попадают в
  таблицу обычных DATA-кадров;
- Comparator сравнивает устойчивые значения байтов, а не физические величины;
- один импорт ограничен 1 000 000 обычных CAN-кадров; для более длинной записи
  программа просит разделить копию трассы в PCAN-View, не изменяя исходник;
- полная декодировка HYDAC/J1939 будет добавляться после подтверждённых записей.
