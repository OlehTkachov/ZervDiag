# CraneCAN ONK-160 Test

Тестовый пассивный анализатор собственного последовательного протокола
ОНК-160С-02 на кране КС-55727. Эта редакция предназначена только для ОНК-160.

> **Главное правило:** программа и адаптер только принимают данные. TX USB-UART
> к трансиверу не подключается. Любые подключения к стенду выполняются при
> снятом питании.

## 1. Что входит в тестовую редакцию

- один профиль `ОНК-160С-02 / КС-55727`;
- приём через виртуальный COM-порт: `38 400 бит/с, 8E1`;
- виртуальный источник для проверки интерфейса без стенда;
- сборка пакетов `CA`, `E5`, `E6`, `E8`, `F7`;
- проверка контрольной суммы: сумма всех байтов пакета по модулю 256 равна `FF`;
- живая расшифровка подтверждённых состояний E31 и E83;
- предварительное распознавание эталонного состояния E55;
- стендовый режим `норма → одно изменение` по 20–50 полным циклам;
- побитовое сравнение, оценка стабильности и отчёт CSV;
- открытие и сохранение исходного журнала CSV.

Драйвер PEAK/PCAN-Basic в решение и исполняемый файл не входит. Обычный
PCAN-USB для потока ОНК-160 не используется: аппаратный CAN-контроллер внутри
него не выдаёт программе нестандартный поток UART.

## 2. Что потребуется

### На стенде

1. Точка подключения ОНК-160: `CAN-H`, `CAN-L`, `GND`.
2. TJA1050 или совместимый дифференциальный приёмник в аппаратном Silent mode.
3. Изолированный USB-UART с VCP-драйвером Windows.
4. Стабилизированные `+5 В` для TJA1050.
5. Преобразователь уровня `5 В → 3,3 В`, если RX используемого USB-UART не
   допускает логический уровень 5 В.

### На компьютере оператора

- Windows 10/11 x64;
- папка автономной сборки `publish\onk160-test-win-x64`;
- VCP-драйвер именно для применённого USB-UART: FTDI, Silicon Labs или другого
  изготовителя.

.NET SDK и .NET Runtime на компьютере оператора не требуются.

## 3. Распиновка — не перепутать две стороны

### Разъём ОНК-160С-02 на исследованном стенде

| Контакт разъёма | Сигнал | Подключить к адаптеру |
|---:|---|---|
| 4 | GND | GND входной стороны адаптера |
| 5 | Экран | по принятой схеме экранирования стенда; не использовать как GND вместо контакта 4 |
| 6 | CAN-H | TJA1050, вывод 7 `CANH` |
| 7 | CAN-L | TJA1050, вывод 6 `CANL` |

Другие контакты разъёма в анализатор не подключать.

### Микросхема TJA1050

| Вывод TJA1050 | Назначение | Подключение |
|---:|---|---|
| 1 | TXD | к `+5 В` через `10 кОм`; к TX USB-UART **не подключать** |
| 2 | GND | GND входной стороны адаптера |
| 3 | VCC | стабилизированные `+5 В`; рядом конденсатор `100 нФ` на GND |
| 4 | RXD | на RX USB-UART через согласование уровня при необходимости |
| 5 | Vref | не подключать |
| 6 | CANL | к контакту 7 разъёма ОНК-160 (`CAN-L`) |
| 7 | CANH | к контакту 6 разъёма ОНК-160 (`CAN-H`) |
| 8 | S | к `+5 В`: Silent mode, передатчик аппаратно отключён |

```text
Разъём ОНК-160                 TJA1050                    USB-UART

контакт 6, CAN-H ──────────── pin 7 CANH
контакт 7, CAN-L ──────────── pin 6 CANL
контакт 4, GND   ──────────── pin 2 GND ─────────────── GND входной стороны

                               pin 3 VCC ─────────────── +5 В
                               pin 8 S   ─────────────── +5 В (Silent)
                    +5 В ─10 кОм─ pin 1 TXD
                               pin 4 RXD ─────────────── RX

                                                         TX — НЕ ПОДКЛЮЧАТЬ
```

Полное описание адаптера: [`docs/ONK160_UART_ADAPTER.md`](docs/ONK160_UART_ADAPTER.md).

## 4. Контроль перед первым включением

Выполнять по порядку. Не пропускать пункты.

- [ ] Питание стенда снято.
- [ ] TX USB-UART физически не подключён к TJA1050.
- [ ] Вывод 8 `S` TJA1050 надёжно подтянут к `+5 В`.
- [ ] CAN-H разъёма ОНК подключён к `CANH` TJA1050, CAN-L — к `CANL`.
- [ ] Контакт 4 разъёма ОНК подключён к GND входной стороны адаптера.
- [ ] Проверено допустимое напряжение входа RX USB-UART; при необходимости
      установлен преобразователь уровня.
- [ ] Между CAN-H и CAN-L обесточенного стенда измерено `60±5 Ом`.
- [ ] Дополнительный терминатор 120 Ом на модуле отключён.
- [ ] В схеме нет соединения от компьютера или USB-UART TX к линии ОНК.
- [ ] Только после этих проверок подано питание стенда.

Если сопротивление линии заметно отличается от `60±5 Ом`, питание не включать:
сначала проверить штатные терминаторы и подключение адаптера.

## 5. Подготовка Windows и COM-порта

1. Не подключая адаптер к стенду, вставьте USB-UART в компьютер.
2. Откройте `Диспетчер устройств` → `Порты (COM и LPT)`.
3. Запишите номер появившегося порта, например `COM4`.
4. Если новый COM-порт не появился, установите VCP-драйвер изготовителя
   USB-UART и снова подключите устройство.
5. Закройте терминальные программы, конфигураторы и другие приложения,
   которые могут удерживать этот COM-порт.

Номер COM-порта относится к USB-UART, а не к PCAN-USB.

## 6. Первый запуск программы

1. Скопируйте на компьютер **всю** папку `onk160-test-win-x64`, а не только EXE.
2. Запустите `CraneCAN.ONK160.Test.exe`.
3. Оставьте профиль `ОНК-160С-02 / КС-55727`.
4. Оставьте источник `ОНК-160 UART (COM, 38400 8E1)`.
5. Нажмите `Обновить`.
6. Выберите записанный ранее COM-порт. Если список пуст, введите, например,
   `COM4` вручную.
7. Убедитесь, что скорость показывает `38400`, а флажок `Только приём`
   установлен и недоступен для изменения.
8. Нажмите `Подключить`.
9. Откройте вкладку `Трафик` и дождитесь пакетов `CA`, `E6`, `E5`, `E8`, `F7`.
10. Проверьте, что в колонке `Тип` повторяется `UART / сумма OK`.

Правильное подключение подтверждают одновременно три признака:

- пакеты повторяются примерно каждые `51 мс`;
- большинство пакетов имеет `UART / сумма OK`;
- вкладка `ОНК-160 — расшифровка` обновляет текущее состояние.

Если виден непрерывный поток одиночных неизвестных байтов или массовые ошибки
контрольной суммы, испытание не начинать. Проверить `CAN-H/CAN-L`, общую землю,
логические уровни RX и параметры `38400, 8E1`.

## 7. Обязательный порядок стендового испытания

Принцип каждого опыта: **одно испытание — одно электрическое изменение**.
Нельзя одновременно отключать датчик, менять другое напряжение и переключать
концевик: программа покажет все отличия, но определить их назначение будет
невозможно.

### Этап A — запись нормы

1. Приведите стенд в исходное исправное состояние.
2. Дождитесь устойчивых показаний БОИ не менее 3 секунд.
3. На вкладке `Стендовые испытания` заполните `Название испытания`.
4. Выберите число циклов:
   - `20` — обычное быстрое испытание;
   - `30–50` — если сигнал или показания нестабильны.
5. Нажмите `1. Записать норму`.
6. До завершения счётчика не менять ни один сигнал и не отключать питание.
7. Дождитесь сообщения `Норма записана`.

Неполная выборка после кнопки `Остановить запись` или отключения COM-порта
автоматически отбрасывается.

### Этап B — одно контролируемое изменение

1. Измените только один заранее выбранный электрический сигнал.
2. Дождитесь устойчивого показания БОИ не менее 3 секунд.
3. Заполните все поля:
   - `Электрическое воздействие` — точное действие и электрический уровень;
   - `Код БОИ` — например `E83`; если кода нет, написать `нет`;
   - `Текст БОИ` — точное показание или описание; если текста нет, написать
     `нет`.
4. Нажмите `2. Записать изменение`.
5. До завершения счётчика не менять сигнал, нагрузку и питание.
6. Дождитесь сообщения `Сравнение готово`.

Программа использует для второй записи то же число циклов, что и для нормы.
Изменить его между этапами нельзя; это защищает сравнение от неравных выборок.

### Этап C — проверка результата

1. Оставьте флажок `Только изменения`.
2. Для каждой строки проверьте:
   - пакет и номер `DATA[n]`;
   - значение в норме и после воздействия;
   - маску `XOR`;
   - переходы битов в формате `номер: было→стало`;
   - стабильность обеих выборок.
3. Строка `Контрольная сумма` изменяется вслед за данными и не является
   самостоятельным сигналом.
4. Если программа сообщает о стабильности ниже 90%, вернуть стенд в норму,
   нажать `Сбросить сравнение` и повторить опыт с 30–50 циклами.
5. Снять воздействие и убедиться, что БОИ вернулся к исходному состоянию.

### Этап D — обязательное сохранение

1. Нажмите `Сохранить отчёт CSV` на вкладке стендовых испытаний.
2. Нажмите `Сохранить CSV` в верхней панели, чтобы сохранить исходный поток.
3. Сохраните оба файла в одной папке.
4. Используйте одно имя опыта, например:

```text
20260826_E83_koncevik_report.csv
20260826_E83_koncevik_trace.csv
```

Не переходить к следующему воздействию, пока оба файла не сохранены и не
проверено их наличие.

## 8. Уже подтверждённые признаки

| Состояние | Пакет | Подтверждение |
|---|---|---|
| Норма датчика давления штоковой полости | `E6 35 00 E4` в исследованном режиме | `raw = 0x0035` |
| E31, неисправность датчика штоковой полости | `E6 00 80 99` | `raw = 0x8000` |
| Норма КОС и концевика подъёма крюка | `F7 81 87` | `STATUS bit 7 = 1` |
| E83, сработал/разомкнут концевик | `F7 01 07` | `STATUS bit 7: 1→0` |
| E55, КОС не отвечает | `F7 10 F8`, иногда затем одиночный `2A` | предварительный эталон |

Одиночный `2A` пока не считать адресом КОС: подтверждена только его корреляция
с наблюдавшимся ошибочным состоянием.

## 9. Типовые ошибки оператора

| Признак | Вероятная причина | Действие |
|---|---|---|
| COM-порт отсутствует | нет VCP-драйвера или неисправен USB-кабель | проверить `Диспетчер устройств`, установить драйвер изготовителя |
| `Порт занят` | COM открыт другой программой | закрыть терминал/конфигуратор и повторить |
| Нет пакетов | перепутаны CAN-H/CAN-L, нет GND или RX подключён неверно | снять питание и проверить распиновку по таблице |
| Много ошибок суммы | неверный уровень RX, плохая земля, помехи или не `38400, 8E1` | остановить испытание и проверить электрическую часть |
| Стабильность ниже 90% | воздействие менялось во время записи либо состояние не установилось | повторить обе записи, увеличить выборку до 30–50 циклов |
| Изменилось много несвязанных байтов | одновременно изменены несколько факторов | вернуть норму и повторить опыт с одним воздействием |
| Изменились только данные и контрольная сумма | ожидаемое поведение | анализировать DATA; контрольную сумму отдельно не трактовать |

## 10. Проверка интерфейса без стенда

1. Выберите источник `Виртуальный ОНК-160 (демонстрация)`.
2. Выберите `Демонстрационный поток ОНК-160`.
3. Нажмите `Подключить`.
4. Проверьте вкладки `Трафик` и `ОНК-160 — расшифровка`.

Виртуальный поток автоматически меняет состояния и предназначен для проверки
интерфейса. Для документированного стендового сравнения использовать реальный
стабильный сигнал либо контролировать момент смены виртуального состояния.

## 11. Сборка на Windows

На компьютере сборки нужны Windows 10/11 x64, .NET 8 SDK и доступ к интернету
при первом восстановлении пакетов.

Откройте PowerShell в каталоге проекта:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\build-windows.ps1
```

Скрипт сначала запускает дымовые тесты, затем создаёт автономную сборку:

```text
publish\onk160-test-win-x64\CraneCAN.ONK160.Test.exe
```

В эту же папку автоматически помещаются `README.md`, схема адаптера в каталоге
`docs` и файл `SHA256SUMS.txt` с контрольной суммой EXE.

## 12. Перенос на другой компьютер

1. Скопировать целиком папку `publish\onk160-test-win-x64`.
2. Установить VCP-драйвер USB-UART.
3. Проверить появление `COMx` в `Диспетчере устройств`.
4. Запустить `CraneCAN.ONK160.Test.exe`.

Если Windows показывает SmartScreen, сверить источник архива и контрольную
сумму файла. Тестовая программа пока не подписана цифровым сертификатом.

## 13. Запрещённые действия

- не подключать обычный USB-UART напрямую к CAN-H/CAN-L;
- не подключать TX USB-UART к TJA1050;
- не переводить TJA1050 из Silent mode;
- не добавлять терминатор при штатных `60±5 Ом`;
- не подключать и не отключать провода при включённом питании стенда;
- не использовать эту редакцию для передачи запросов, имитации узлов или
  записи памяти БОИ;
- не переносить неподтверждённую расшифровку на рабочий кран без отдельной
  проверки.
